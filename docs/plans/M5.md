# M5 plan: signing

Goal: `sign-bundle` works against staging and production, including the
Rekor v2 signing-config test, so the strict xfail list drops to the one
permanent intoto case.

## Step 1: HTTP (decided 2026-09-29)

- `sigstore_http` declares exactly hex_core's `request/5` callback (same
  method atoms, `#{binary() => binary()}` headers, `{ContentType, Body} |
  undefined` body, `{ok, {Status, Headers, Body}} | {error, _}`). hex can
  pass its configured adapter through unchanged; behaviours are compile-
  time only, so its module name (mix_/r3_ prefixed) never matters to us.
  No `request_to_file`: nothing in Sigstore downloads large files.
- Shared layer adds: User-Agent unless set, JCS-encoded JSON requests and
  adapter-decoded JSON responses, per-call retry policy (`idempotent`
  retries 5xx and connection failures; `connect_only` retries only when the
  request provably never reached the server, for Rekor uploads).
- Default adapter `sigstore_http_httpc`: TLS verification is mandatory
  (verify_peer, OS CA store, HTTPS hostname check) and cannot be turned
  off; https only unless `allow_http` is set; 30 s default timeout for
  Rekor v2's blocking upload; never starts inets/ssl itself.
- Tests: a stub adapter for protocol logic, and a real TLS round trip
  against a local `ssl` server with a minted certificate (accepts the right
  host, rejects an untrusted chain and a wrong hostname).
