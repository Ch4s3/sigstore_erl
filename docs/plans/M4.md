# M4 plan: RFC 3161 timestamps

Goal: verify TSA timestamps so every verification-only conformance
fixture reaches its intended result, and no bundle ends `incomplete`.

## Decisions

- **Hand-written DER for the whole token**, not just TSTInfo. OTP 25 ships
  the CMS types as `'PKCS-7'`, OTP 29 as `'CryptographicMessageSyntax-2009'`;
  depending on either breaks vendoring on some OTP in hex's range. SPEC D2
  revised accordingly.
- **Only trust-root TSA certificates are trusted.** Certificates embedded in
  a response never become trust anchors; a response is valid only if it
  verifies with the leaf of a trust-root TSA chain (untrusted-tsa fixtures).
- **Hybrid model**: the TSA chain is validated at the timestamp's `genTime`,
  and the TSA entry's `validFor` must cover `genTime` (inclusive).
- **Rekor v2 key validity** (carried from M3): the matched tlog key's
  `validFor` must cover every verified TSA time.

## Steps

1. `sigstore_der`: OID and INTEGER decoding, GeneralizedTime parsing.
2. `sigstore_tsa`: parse TimeStampResp → status, SignedData, TSTInfo;
   check status granted, content type id-ct-TSTInfo, messageImprint =
   H(signature bytes), signed-attribute messageDigest = H(TSTInfo), CMS
   signature over the re-tagged signed attributes with the TSA leaf key,
   timeStamping EKU, chain at genTime, TSA validFor.
3. Pipeline: TSA times join SET times; v2 tlog validity checked; nothing
   pending means `{ok, _}`.
4. Ratchet + strict xfail (reproduce CPython locally first).

## Outcome (2026-09-29)

All steps done. 66 CT cases green on OTP 29; xref, dialyzer, erlfmt clean.

**Verification is complete.** 20 of 21 should-pass fixtures verify; the
21st (`intoto-with-custom-trust-root`) is the permanent D10 exclusion. No
`_fail` fixture verifies. All 81 CPython release bundles still verify. The
strict xfail list is now only signing (M5) plus the permanent intoto case.

| Fixtures | Count |
|---|---|
| verify (`ok`) | 20 |
| rejected structurally | 11 |
| rejected by a verification step | 39 |

Timestamp `_fail` fixtures each stop where their README says: imprint
mismatch, TSA outside trust-root validity, TSA certificate expired at
genTime, untrusted TSA (with and without an embedded certificate), and a
timestamp outside the signing certificate's lifetime.

Also landed:

- Rekor v2 log keys are checked against the verified TSA times (inclusive),
  closing the M3 carry-over; tested by narrowing a real root's key window.
- The pipeline has no `incomplete` state any more: every bundle either
  verifies or fails with a tagged reason.
- Mutation test over every prefix and byte flip of a real TSA token.

Found on the way:

- OTP 25 ships CMS as `'PKCS-7'`, OTP 29 as
  `'CryptographicMessageSyntax-2009'`, so the whole token is hand-parsed.
- First CI run on GitHub: rebar3 >= 3.25 cannot run on OTP 25 (pinned
  3.22.1 there), and xref flagged the guarded OTP 27 `json` call on 25/26.
  A module-level `-ignore_xref` does not cover xref's undefined-function
  check (rebar3 looks up ignores on the missing module), so the ignore
  lives in `rebar.config`.
