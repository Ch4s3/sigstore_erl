# M2 plan: certificates, SCTs, identity policy, signatures

Goal: every verification step that does not need the transparency log (M3)
or RFC 3161 timestamps (M4) runs for real, on every fixture.

## The time problem

Chain validation happens *at a signed time*, and signed times only become
trustworthy once M3 verifies the SET/inclusion proof or M4 verifies a TSA
token. M2 therefore validates against the entry's **claimed** integrated
time (Rekor v1 entries only), flags it as unverified, and never returns
success: `sigstore_verify` ends with

    {error, {verify, {incomplete, [tlog | tsa]}}}

meaning "every implemented step passed; these are still missing". That
makes progress testable: happy paths must reach `incomplete`, and each
`_fail` fixture must fail at a named step.

## Steps

1. **`sigstore_der`**: minimal DER TLV reader (lengths, tags, UTF8String).
   Also used by SCT lists now and TSTInfo in M4.
2. **`sigstore_x509`**: decode; X.509 time → `sigstore_time:t()`; SAN and
   Fulcio extension extraction (`.1.1` raw bytes, `.1.8`+ DER UTF8String);
   leaf profile; chain building and validation at time T against trust-root
   CAs valid at T (hand-rolled, SPEC §6.2: OTP validates at wall-clock only).
3. **`sigstore_sct`**: port the proven probe: embedded SCT, precert TBS,
   issuer selection (precert-signing EKU), CT key by log ID and time, with
   fall back to all CT keys.
4. **`sigstore_policy`**: identity (rfc822 / URI / otherName) + issuer,
   `all_of` / `any_of`, extension policies.
5. **`sigstore_dsse` + `sigstore_intoto`**: PAE, Statement v1 subjects.
6. **Signatures**: message signature over the artifact digest (hash chosen
   by key algorithm; `messageDigest` must match but is never trusted),
   DSSE over PAE, managed keys.
7. **`sigstore_verify` composition** in client-spec order, with the
   `incomplete` terminal error; integrated time in the future rejected.
8. **Fixture ratchet**: each of the 70 fixtures is pinned to the stage it
   stops at; the table changes only deliberately.

## Done when

- Every happy-path fixture reaches `incomplete` (none fails early).
- Each `_fail` fixture that M2 can detect fails at the step its README
  names; the rest reach `incomplete` (they need M3/M4).
- All checks green; vendor list updated.

## Outcome (2026-09-29)

All steps done. 52 CT cases green on OTP 29; xref, dialyzer, erlfmt clean.

Fixture ratchet (`sigstore_fixtures_SUITE:verify_stages/1`, all 70 pinned):

| Stops at | Count |
|---|---|
| structural parse (M1) | 11 |
| M2 step (chain, SCT, policy, signature, digest) | 12 |
| `incomplete` (needs M3 tlog / M4 TSA) | 47, including all 21 happy paths |

M2 catches `bundle-from-wrong-instance`, `dsse-invalid-sig`,
`rekor2-dsse-invalid-sig`, `integrated-time-in-future`,
`intoto-expired-certificate`, `intoto-set-outside-signing-cert-validity`,
`invalid-ct-key`, `managed-key-no-key`, `managed-key-wrong-key`,
`message-digest-mismatch`, `signature-mismatch`, `wrong-material`, each
checked against its README.

Bugs found on the way:

- A fun-head pattern shadowed the expected `messageDigest` instead of
  matching it, which would have accepted any digest. The compiler's
  "clause cannot match" warning caught it; fixed with a guard.
- OTP renamed the SAN otherName record across versions; matched by
  tuple shape so the 25..29 range works.
- `pkix_test_data` option order: proplists take the first match, so
  per-cert overrides must come first. Tests now assert the minted
  certificates really have the overridden property.

Limitations carried forward:

- Chain validation uses the entry's *claimed* integrated time. M3 makes it
  verified; until then the pipeline can only end in `incomplete`.
- Rekor v2 bundles have only TSA time, so chain and SCT checks are skipped
  for them until M4 parses the timestamp.
