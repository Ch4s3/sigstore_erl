# M3 plan: transparency log

Goal: verify every tlog entry (checkpoint, inclusion proof, SET, body vs
bundle), which turns Rekor v1 integrated time into a *verified* signed
time. Bundles with no TSA timestamps can then verify end to end.

## Decisions

- **Q7 resolved: no `intoto 0.0.2` support.** It is deprecated Rekor v1,
  sigstore-python does not verify it, and the conformance README suggests
  xfailing it. The parser keeps accepting it; the tlog step rejects it with
  `{tlog, {unsupported_entry, intoto}}`. `intoto-with-custom-trust-root`
  stays xfailed permanently.
- **Pipeline order changes**: the tlog step runs before signed times, since
  a SET must verify before its integrated time counts as signed.
- **Rekor v2 tlog key validity** needs the TSA time (M4). Until then v2
  keys are selected without a validity check and the result stays
  `incomplete [tsa]`; M4 adds the time check.

## Steps

1. `sigstore_merkle`: RFC 6962 leaf/node hashing and inclusion proof
   (transparency-dev algorithm, proof length = inner + border).
2. `sigstore_checkpoint`: C2SP signed-note parse (origin, size, root,
   extension lines; `— name base64(hint4||sig)` lines); key hint per log
   key type computed from **the signature line's name**; ignore unknown
   lines, require one verifying log signature.
3. SET (Rekor v1): JCS of body/integratedTime/logID(hex)/logIndex(global).
4. Body cross-check: hashedrekord 0.0.1, dsse 0.0.1, hashedrekord 0.0.2
   (DSSE bundles: digest = SHA-256(PAE)); compare decoded values, not text.
5. Pipeline: material → tlog → signed times (verified SETs only) → chain →
   SCT → policy → signature → `{ok, verified()}` when nothing is pending.
6. Ratchet + conformance xfail: remove exactly the fixtures that now pass.

## Outcome (2026-09-29)

All steps done. 61 CT cases green on OTP 29; xref, dialyzer, erlfmt clean.

**First end-to-end verifications.** 7 conformance fixtures now verify
(every Rekor v1 happy path without a TSA timestamp), with both file and
`sha256:` digest input through the escript. All 81 CPython release bundles
in the conformance suite's pinned tracker verify too. Both were removed
from the strict xfail list, which now holds only signing (M5), 13 fixtures
needing M4, and the permanent `intoto` case.

| Stops at | Count |
|---|---|
| verifies (`ok`) | 7 |
| structural parse | 11 |
| verification step | 38 |
| `incomplete [tsa]` (M4) | 14 |

Every Rekor v2 happy path passes checkpoint, inclusion proof, and body
checks (Ed25519 name-bound key hints, witness cosignatures ignored).

Bugs found:

- **Hash chosen from the key curve.** ECDSA does not bind hash to curve;
  CPython releases pair a P-384 Fulcio key with a SHA-256 digest. 59 of 81
  releases failed until the prehash came from the declared `messageDigest`
  algorithm. No conformance fixture covers this; a real CPython bundle is
  now a regression vector (`test/vectors/cpython`).
- **Checkpoint parser raised** on an empty signature block. Fixed, and a
  mutation test now feeds every prefix and byte flip of real v1/v2
  checkpoints through parse+verify, asserting tagged errors only.

Q7 resolved: `intoto 0.0.2` is rejected at the tlog step; the one happy
fixture using it is a permanent xfail.

Carried to M4: Rekor v2 tlog keys are matched without a validity check
until the TSA time exists; M4 must add it.
