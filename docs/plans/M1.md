# M1 plan: data models and structural validation

Goal: every bundle and trust root the conformance suite feeds us is parsed
into a normalised map, and every *structurally* broken fixture is rejected
with a tagged error. No cryptography yet (that is M2/M3).

Conformance fixtures pinned at sigstore-conformance@767b4a7.

## Steps

1. **Fix M0 conformance xfail.** Strict xfail on `test_*` fails the 98
   `_fail` verify cases the stub already rejects. xfail only the cases
   expected to fail today: signing tests and non-`_fail` verify cases.
2. **Test JSON adapter for OTP 25/26.** A small decoder in `test/` (not
   shipped) plugged in via `json_adapter` when OTP `json` is absent, so the
   CI matrix can run every suite. Doubles as proof the adapter path works.
3. **`sigstore_jcs`.** RFC 8785 encoder: sorted keys by UTF-16 code units,
   RFC 8785 string escaping, integers, booleans, null; floats rejected.
   Test vectors from RFC 8785 plus Sigstore SET payload shape.
4. **`sigstore_b64`.** Strict standard base64 (padded; tolerate no
   padding only where protobuf JSON allows), hex helpers. Never raises.
5. **`sigstore_keys`.** `PublicKeyDetails` ↔ OTP key term, SPKI DER decode,
   `SHA-256(SPKI)` key IDs, managed-key PEM loading.
6. **`sigstore_bundle`.** Parse → normalised map (bytes decoded, int64 as
   integers), every structural check in SPEC §5.1, emit via JCS.
7. **`sigstore_trust`.** TrustedRoot + SigningConfig parse (all accepted
   media types, ClientTrustConfig unwrap), inclusive time ranges, selectors.
8. **Embedded trust roots.** `scripts/embed_trust_roots.sh` generates the
   checked-in `sigstore_trust_embedded.erl` (prod + staging trusted root and
   signing config) with source URL and sha256 in the header.
9. **Conformance escript.** `verify-bundle` loads trust root (flag, else
   embedded by instance), managed key, bundle; runs structural validation;
   then returns `{verify, not_implemented}` until M2.
10. **Vendorability CT test** (SPEC §2a V7/V9): vendor twice, compile.
11. **Fixture suite.** Copy the conformance `bundle-verify` fixtures into
    `test/vectors/bundle-verify/`; a CT suite asserts which ones fail
    structurally and that every happy path parses.

## Done when

- `rebar3 ct`, `xref`, `dialyzer`, `fmt --check` green on OTP 29 locally.
- Every happy-path fixture parses; the structural `_fail` fixtures are
  rejected at parse time with the expected tagged reason.
- Conformance workflow xfail list is precise, not a blanket glob.

## Outcome (2026-09-28)

All steps done. 38 CT cases green on OTP 29; xref, dialyzer, erlfmt clean.

- 11 of 70 fixtures are rejected structurally, each for its README's reason
  (`invalid-inclusion-proof_fail` for a stricter correct one: v0.2+ needs a
  checkpoint). The other 59 parse and round-trip through `to_json/1`.
- The double-vendoring test (`a_` then `b_a_`) compiles, finds no leaked
  module atoms, and runs the vendored parser on a real fixture.

Findings that changed the design (recorded in SPEC):

- Proto3 JSON `null` means unset; real roots use it. Nulls are stripped.
- A fixture has line-wrapped base64; `\r\n` are now skipped, as Go,
  Python, and sigstore-rs do.
- Six v0.2 fixtures use deprecated `intoto 0.0.2` entries (Q7).
- Internal model switched to atom keys (D3 revised).
- The M0 conformance workflow was red: strict xfail on `test_*` failed the
  98 `_fail` cases the stub already rejected. xfail is now an explicit list.

Not done here, by design: any signature, chain, SCT, proof, or timestamp
verification (M2-M4).
